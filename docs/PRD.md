# TodoList for Windows 简单 PRD

## 1. 项目信息

- **Language**：中文
- **Programming Language**：C++20；纯 Win32 API；Direct2D 1.1 + DirectWrite；MySQL Connector/C++ 8.0 静态链接；Visual Studio 2022
- **Project Name**：`todolist4win_mysql`
- **目标平台**：Windows 10 1903+ / Windows 11，Win64；Per-Monitor V2，100%–200% DPI
- **原始需求复述**：交付一款本地单用户 Windows 原生 Todo 桌面应用。应用以 iOS 26 Liquid Glass 为视觉参考，采用无边框悬浮玻璃窗口和全自绘控件，完整支持任务、分类、系统视图、历史、统计、拖拽排序、快捷键和托盘；数据实时持久化到本机 MySQL，启动自动初始化数据库，异常时友好降级且不得损坏已有数据。最终需满足冷启动、动画帧率、空闲内存和本地查询响应目标，但所有指标均须实测后才能声明达成。

### 范围边界

- 本期为 Win64 单机应用，默认连接本机 MySQL，不包含多人协作、账号体系、云同步和移动端。
- 禁止 Qt、MFC、wxWidgets；窗口消息循环、输入框、复选框、按钮、右键菜单和滚动条均自绘。
- 核心逻辑、UI、数据库三层解耦；UI 不直接拼接 SQL，数据库层不依赖窗口控件。
- P0 先形成可验证业务闭环，P1 完成高保真视觉、动效与性能目标；**P1 仍是完整交付验收范围，并非默认砍掉的可选项**。P2 为后续候选，不纳入本期承诺。

## 2. 产品定义

### 2.1 Product Goals

1. **可靠管理任务**：用户可完成新建、编辑、完成、分类、查找、排序、历史恢复和统计的闭环，重启后数据与排序不丢失。
2. **提供一致的原生玻璃体验**：在 Win32 上呈现符合参考的 Liquid Glass 布局、色彩、交互和亮暗主题，并适配多 DPI。
3. **确保本地数据韧性与可恢复性**：数据库初始化、重连、事务和错误提示清晰可验证，非法输入或连接异常不得导致崩溃或已有数据丢失。

### 2.2 User Stories

- As a Windows 用户，I want 通过顶部输入框和快捷键快速记录任务，so that 不打断当前工作即可捕捉待办。
- As a 任务管理者，I want 使用分类、今日、逾期、搜索和拖拽排序组织任务，so that 能快速确定下一步行动。
- As a 需要追溯记录的用户，I want 已完成任务自动进入历史并可筛选、恢复或永久删除，so that 待办列表保持清爽且记录可追溯。
- As a 数据复盘用户，I want 查看完成率、分类完成情况和近 7 天趋势，so that 能判断任务负荷与执行变化。
- As a 高频桌面用户，I want 使用置顶、托盘、快捷键及亮暗主题，so that 应用能融入持续使用的桌面环境。

## 4. UI Design Draft

### 4.1 主窗口

- **标题栏**：左侧应用图标与标题；右侧依次为置顶、最小化、最大化、关闭圆形玻璃按钮。标题栏空白区可拖动，边缘可缩放。
- **左侧悬浮导航**：系统视图（全部任务、今日待办、逾期任务）、用户分类、历史、统计；显示当前选中态及实时数量，不与窗口边缘贴合。
- **右侧顶部玻璃条**：提供新建任务入口、优先级/截止日期/分类设置，以及搜索和筛选；空间不足时可分行，不得压缩到无法操作。
- **中部任务列表**：卡片展示完成框、标题、优先级、截止日期和分类；悬停出现删除；双击进入编辑；拖拽时显示半透明占位。
- **底部概览玻璃条**：待办、已完成、逾期、今日完成四项实时更新。
- **反馈状态**：空列表展示线性图标和新建引导；数据库错误展示原因摘要、重试和连接配置，不用技术堆栈代替用户提示。

### 4.2 历史与统计

- **历史页**：顶部为时间范围、分类、关键词筛选和批量操作区；列表显示任务快照、原分类、创建及完成时间；支持单条/批量恢复和永久删除。
- **统计页**：完成率环形图、分类横向柱状图、近 7 天折线图按统一数据口径展示；无数据时显示零态而非空白画布。

## 5. 数据与一致性要求

- 自动创建数据库 `todolist_db`，至少包含：
  - `category(id, name, color, created_at)`
  - `task(id, category_id, title, note, priority, due_time, completed, created_at, completed_at, sort_weight)`
  - `history(id, task snapshot, original_category_id, completed_at, operation_type)`
- 历史快照至少能还原标题、备注、优先级、截止日期、原分类、创建时间和完成时间；具体列定义及 `operation_type` 取值须在 Q2 确认后固化。
- 完成/取消完成、恢复、永久删除、分类变更和排序均须保证数据库与内存状态一致；跨表写入使用事务，失败整体回滚。
- 所有写操作应有明确成功/失败结果；数据库失败时不得仅更新 UI 制造“已保存”假象。
- 默认统计语义：逾期仅指未完成且已超过截止时间的任务；今日完成按本地自然日计算；近 7 天包含今天。留底、归档及重复完成的去重口径待 Q2 确认。
- 对空标题、非法颜色、非法优先级、失效分类和损坏时间值进行校验或隔离，不能因单条坏数据导致应用崩溃或清空其他数据。

## 7. 最终验收目标

以下为**目标而非当前实测结论**：

| 维度 | 目标 | 验收说明 |
| --- | --- | --- |
| 业务闭环 | P0 全部通过 | 新建至完成、历史、恢复、统计及重启持久化链路无数据重复或丢失。 |
| 系统兼容 | Windows 10 1903+/11，Win64，100%–200% DPI | 覆盖窗口缩放、多显示器、亮暗主题和托盘恢复。 |
| 冷启动 | <800ms | 建议从进程启动计至主窗口可交互；本机 MySQL 可用与不可用场景分别记录。 |
| 动画 | 60fps 目标 | 覆盖复选框、新增、删除、拖拽、主题切换和图表；记录持续掉帧而非只报平均值。 |
| 空闲内存 | <35MB | 建议主窗口稳定空闲 60 秒后测量，并明确所用内存指标。 |
| 本地查询 | 无感知延迟 | 建议以 P95 <100ms 为量化起点，最终按 Q7 的数据规模与硬件确认。 |
| 故障安全 | 不崩溃、不静默丢数据 | 覆盖停库、断连、重复启动、非法输入、损坏记录及事务失败。 |

## 8. Open Questions（真正影响实现或验收）

1. **Q1 视觉基准（阻塞 P1 高保真验收）**：是否有指定的 iOS 26 Liquid Glass 截图、设计稿或录屏，以及模糊半径、透明度、高光和间距容差？若无，建议以本 PRD 的文字参数制作视觉基线，由需求方确认后再称为“严格符合参考”。
2. **Q2 完成、归档、历史与统计口径（阻塞数据模型）**：完成时是否始终保留 `task` 行并追加一条 `history`，归档仅是隐藏完成项？恢复是更新原任务还是新建任务？重复完成是否生成多条历史？建议“原任务存在则原位恢复、不重复建行；每次完成记录独立事件”，并需同时确认统计按任务去重还是按完成事件计数。
3. **Q3 删除与关联规则（阻塞事务和约束）**：删除未完成待办是否保留历史；删除仍有任务的分类时应阻止、迁移还是级联？建议非空分类先阻止删除并要求迁移，永久删除二次确认，历史快照不随分类改名而改写。
4. **Q4 拖拽排序范围（阻塞 `sort_weight` 设计）**：手动顺序是全局一套、每分类一套，还是每个系统视图各一套？建议在全部任务和用户分类中允许手动排序；今日/逾期默认按截止时间再按权重排序，是否仍需在这两个视图拖拽需确认。
5. **Q5 截止日期语义（阻塞查询和逾期判断）**：用户选择“截止日期”时是否表示本地日期当天 23:59:59，还是需要具体到时分？建议默认本地当天结束，并明确跨时区不作为本期能力。
6. **Q6 固定连接与可修改配置的关系（阻塞配置层）**：是否采用“题述连接为默认值，用户修改后持久化覆盖”的方式？建议如此处理，并确认配置保存位置、凭据保护要求，以及连接失败时是否允许只读浏览已加载数据。
7. **Q7 性能与列表规模（阻塞优化和最终验收）**：目标硬件、数据库版本、最大任务/历史量及典型数据量是多少？建议至少给出 1 万任务、10 万历史记录的验收数据集；是否启用列表虚拟化及相应内存口径需据此确定。
